# FM255 Proteus 8 implementation status

## What is prepared
- Schematic reference drawing (SVG).
- Nine unique device-pin numbers for the two connectors.
- Connector-to-device pin mapping in `PROTEUS8_PIN_MAP.csv`.
- Pinout, mechanical notes, and simulation limitations.

## Important distinction
The files in this folder are **design source/reference assets**, not a compiled native Proteus device library. A Proteus 8 device must be created with ISIS's **Make Device** workflow and saved into a writable library. The native library/index output must be generated by Proteus itself and then tested by placing the part in a new schematic.

## Pin mapping convention
The physical connector pins retain their own numbering in the CSV. Proteus device pin numbers must be unique across the complete device, so J1 uses device pins 1–4 and J2 uses device pins 5–9. The USB connector's physical pins 1–5 map to device pins 5–9 respectively.

## What is not verified
- VCC operating range and current requirement.
- UART voltage level and baud/protocol.
- Exact connector manufacturer/series and footprint.
- Full module outline, mounting-hole coordinates, and board length.
- Any internal simulation behavior or manufacturer VSM model.

Do not fabricate a PCB from the schematic reference. Do not connect power or logic until the electrical limits are confirmed from the module documentation.

## Final local validation checklist
1. Create the FM255 body and nine pins in Proteus 8 ISIS.
2. Assign the device pin numbers exactly as in the CSV.
3. Use the Make Device command and save to a writable custom library.
4. Close and reopen Proteus; search for FM255 in Pick Devices.
5. Place it on a fresh schematic and inspect all nine pin numbers/names.
6. Export/backup the generated library files and add them to this repository only after the component is confirmed to load correctly.
